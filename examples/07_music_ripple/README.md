# 07_music_ripple: YouTube の音に合わせて光らせる

[← リポジトリの README に戻る](../../README.md)（ビルド環境の準備、書き込み方法など）

ブラウザで YouTube の動画を再生し、その音を解析して LED を光らせます。

- **ビート**：中心から四角い波紋が、2x2 → 4x4 → 6x6 → 8x8 の順に外へ広がる（小節の頭は強い波紋）
- **音の出だし（オンセット）**：ランダムな 1 点が星のように光って消える
- 色相は時間とともに少しずつ虹色に変わる

8x8 では円の波紋はぼやけて見えるので、ピクセルの格子に沿った四角い輪（中心からのチェビシェフ距離で 4 段階）にしています。ボードとの接続は [06_ble_color](../06_ble_color/README.md) と同じく Web Bluetooth です。

## 仕組み

埋め込んだ YouTube（iframe）は別オリジンなので、ページから音声データを直接は読めません。そこで、Chrome の画面共有 API（`getDisplayMedia`）で**自分のタブの音声**を取り込み、ブラウザ内で解析します。

```text
[Chrome]  YouTube iframe ──タブ音声の取り込み (22050Hz)──┬─▶ AnalyserNode: 低音レベル / オンセット
                                                        │
                                                        └─▶ AudioWorklet ─▶ 振幅スペクトル (50 フレーム/秒)
                                                                              │ 直近 7.7 秒
                                                                              ▼
                                                     Web Worker: Beat This! (onnxruntime-web)
                                                                              │ フレームごとのビート確率
                                                                              ▼
                                                     テンポと位相を推定し、次のビートを予測
                                                                              │ BLE で 4 バイト
[ボード]  ◀───────────────────────────────────────────────────────────────────┘
          番号が変わったら波紋や星を出す。アニメーションはボード側で約 40fps で描く
```

ビートの検出には、論文 [Beat This! Accurate Beat Tracking Without DBN Postprocessing](https://arxiv.org/abs/2407.21658)（Foscarin, Schlüter, Widmer, ISMIR 2024）の学習済みモデル [CPJKU/beat_this](https://github.com/CPJKU/beat_this)（MIT License）を使っています。PyTorch のモデルを ONNX に変換して、ブラウザ内で動かしています（WebGPU が使えれば WebGPU、使えなければ WASM）。

このモデルは、曲全体を前後両方向から見て判断する**オフライン用**です。直近の音だけを入れると、右端（＝今）付近のビートは未来の音が見えないぶん不確かになります。そこでリアルタイムでは次のようにしています（[web/beat/tracker.js](web/beat/tracker.js)）。

1. 直近 384 フレーム（約 7.7 秒）で推論を繰り返し、新しい結果でロジットを上書きする
2. 右端から 0.5 秒以上前の部分だけで、論文と同じ最小限の後処理（±70ms の最大値で確率 0.5 超え）でビートを確定する
3. 確定したビートからテンポと位相を求めて、これから来るビートの時刻を予測し、その時刻に光らせる。テンポの候補は「格子に乗るビートの数」で選び、モデルが拍と半拍の間で揺れても切り替わりにくくしている
4. ダウンビート（小節の頭）も同じように確定し、小節の拍数を数えて予測する

そのため、曲の頭や大きくテンポが変わった直後の 2〜4 秒は光りません。

**オンセット（音の出だし）** は従来どおり `AnalyserNode` で検出します。40Hz〜5kHz で前のフレームより強くなった成分の合計（spectral flux）が、直近約 0.7 秒の「平均 + k × 標準偏差」を超えたときです。ビートの分かりにくい曲向けの補助で、直近 1.2 秒にビートがあれば使いません。モデルを読み込めない場合や「使わない」を選んだ場合は、ビートも従来の方法（低音のエネルギーが最近の平均より大きく跳ね上がったとき）で検出します。

ビートの判定はブラウザで、描画はボードで行います。BLE の書き込みは応答待ちが必要で、毎秒 20〜30 回程度が上限の見込みです。この分担にしておくと、通信の間隔が空いてもアニメーションは滑らかに動きます。ビートとオンセットはそれぞれ「番号」で送るので、途中の書き込みが最新値で上書きされても、ビートを取りこぼしません。

### モデル

| モデル | 大きさ | 推論 1 回の目安（窓 7.7 秒） |
| --- | --- | --- |
| small0（既定） | 約 11MB | WebGPU 50〜70ms / WASM 350〜450ms |
| final0 | 約 84MB | WebGPU 約 110ms（WASM では遅すぎて使えません） |

モデルのファイルはリポジトリに含めていません。`make serve EXAMPLE=07_music_ripple` を実行すると、`web/models/beat_this_small0.onnx` がなければ、学習済みのチェックポイントを公式の配布元からダウンロードして ONNX に変換します（[tools/fetch_model.sh](tools/fetch_model.sh)）。

- 初回だけ、`tools/.venv` に PyTorch などをインストールします（数百 MB、1 分ほど）。Python 3.10 以降が必要です（macOS 標準の `python3` は 3.9 なので、`brew install python` などで入れてください）。
- チェックポイントは `~/.cache/torch/hub/checkpoints` に保存されます。
- final0 を使う場合は、別に `make model MODEL=final0` を実行してください。

変換したモデルの入力は 22050Hz の音の振幅スペクトル（窓 1024 点、ホップ 441 点）で、メルフィルタと対数圧縮はモデル側に含めています。ブラウザ側は FFT だけを計算します（[web/beat/dsp.js](web/beat/dsp.js)）。

## 手順

1. ボードに書き込む（TinyGo 0.42 以降）

   ```sh
   make flash EXAMPLE=07_music_ripple
   ```

   BLE の準備ができると、中心から弱い波紋がゆっくり出る待機表示になります。

2. ページを配信する

   ```sh
   make serve EXAMPLE=07_music_ripple
   ```

   初回は、ビート検出のモデルのダウンロードと変換が先に行われます（[モデル](#モデル)を参照）。

3. Chrome で <http://localhost:8080> を開き、次の順に操作する
   1. 「接続する」を押して `S3-Matrix` を選ぶ
   2. YouTube の URL（または動画 ID）を入力して「読み込む」を押し、再生する
   3. 「このタブの音声を取り込む」を押す。共有ダイアログで**このタブ**を選び、**「タブの音声も共有する」をオン**にして共有する

   ページのメーターが低音に合わせて動き、ビートで丸が光れば解析できています（ビートは青、小節の頭はオレンジ、オンセットは紫）。ステータスにテンポ（BPM）が出ます。

   LED が音より遅れて見える、または早すぎる場合は「タイミング補正」を調整してください（既定は 100ms 早める）。BLE の通信と LED の描画にかかる時間を見込んで、予測したビートより早めに送っています。

## 注意

- 使えるのは Chrome / Edge のデスクトップ版だけです（タブ音声の取り込みに対応していないブラウザがあるため）。
- onnxruntime-web は CDN（jsDelivr）から読み込むので、インターネット接続が必要です。
- 埋め込み再生が許可されていない動画は再生できません。
- タブを裏に回すと `requestAnimationFrame` が止まり、解析も止まります。このタブを表示したままにしてください。
- 音の情報が 1.5 秒以上届かないと、ボードは待機表示に戻ります（一時停止したときなど）。
- 波紋の速さ・残像の長さ、星の消え方、色相が変わる速さは [main.go](main.go) 冒頭の定数で調整できます。

| 項目 | UUID | 内容 |
| --- | --- | --- |
| サービス | `6e400011-7a3c-4f1b-9d2e-5c8b1f0a3e01` | 06 とは別の UUID（06 のページで接続しても、サービスが見つからずエラーになる） |

| 輝度 | `6e400013-7a3c-4f1b-9d2e-5c8b1f0a3e01` | 1 バイト（06 と同じ）。Read / Write |
